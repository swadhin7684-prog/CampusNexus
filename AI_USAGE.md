## 1. Runtime AI Inside the Product

### A. Model & Provider
* **Model:** Google Gemini API (`gemini-2.5-flash` / Google Generative AI) with fallback to deterministic local semantic parsing when offline or without API keys.
* **Purpose:**
  1. **Natural-Language Booking Parser (English & Hinglish):** Converts unstructured user prompts (e.g. *"seminar hall kal shaam 6 baje, 2 ghante, 100 log, mic chahiye"*) into structured booking JSON fields (`attendance`, `duration_periods`, `windows`, `needs`, `room_types`, `mandatory_for_groups`).
  2. **Intelligent Conflict & Assumption Detection:** Detects implicit contradictions (e.g., requesting `SH-2` for a wheelchair-accessible session when `SH-2` is not accessible, and proactively suggesting `SH-1`), and resolves ambiguous phrases like *"after lunch"* $\rightarrow$ P6.
  3. **Natural-Language Decision Explainer:** Generates transparent, human-readable explanations when asked why a class was scheduled at 8 AM, why a booking was rejected, or why an alternative venue was offered.

### B. Prompt Location
* All runtime system prompts, few-shot examples, and Pydantic schemas are centrally defined in:
  `backend/app/engines/ai_assistant.py`

### C. What the LLM is NOT Allowed to Decide (Crucial Security & Correctness Boundary)
Per Section 6 rules:
> *"The LLM can read requests, ask follow-up questions, fill in forms and explain decisions. It can't be what decides whether a schedule or booking is valid. That has to be done by your own code..."*

* **The LLM never approves, rejects, or applies any schedule or booking change.**
* Every output generated by the LLM is treated as a **draft proposal**:
  1. The user is presented with an editable structured booking form to review and modify before submitting.
  2. All booking submissions and schedule modifications are strictly passed through the underlying deterministic constraint checkers (`validator.py` and Google OR-Tools CP-SAT engine) before touching any database or schedule state.
* If the Gemini API key is missing or rate-limited, the application automatically falls back to deterministic rule-based NLP extraction and the manual booking form remains 100% operational.
